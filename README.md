# Softheart

Softheart is a React prototype for an AI relationship companion. The app lets users talk through relationship confusion, breakup pain, and rebuilding after heartbreak, then returns emotionally grounded guidance with a clear next step.

The current build is frontend-only. It simulates Softheart's response logic locally and includes browser-based voice input and spoken replies where supported.

## Features

- Relationship clarity mode for mixed signals, conflict, and uncertainty
- Breakup recovery mode with phase detection and no-contact tracking
- Rebuilding mode for self-respect, standards, and identity recovery
- Conversation UI with reflection, clarifying questions, advice, and next steps
- Pattern tracking for repeated dynamics like inconsistency or emotional unsafety
- Journaling prompts based on the current situation
- Voice mode using the browser Web Speech APIs
- Voice style and installed voice selection controls

## Tech Stack

- React
- Vite
- Browser Speech Recognition API
- Browser Speech Synthesis API

## Getting Started

Install dependencies:

```bash
npm install
```

Run the local dev server:

```bash
npm run dev
```

Open the URL printed by Vite, usually:

```text
http://localhost:5173
```

Build for production:

```bash
npm run build
```

Preview the production build:

```bash
npm run preview
```

## Voice Mode

Voice mode works best in browsers with strong Web Speech API support, usually Chrome or Edge. Users tap the mic button once to start talking, then tap it again when they are done. Softheart transcribes the story, generates a response, and speaks it back.

Browser-native voices can sound robotic depending on the user's device and installed voices. For a production-quality emotional voice experience, replace the browser speech layer with a realtime speech-to-text and text-to-speech service.

## Current Limitations

- Responses are generated by local demo logic, not a real AI backend yet.
- Memory is stored only in the current browser session state.
- Safety detection is basic and should be replaced with a proper moderation layer before production use.
- Voice reliability depends on browser support and microphone permissions.
